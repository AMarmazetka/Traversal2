Invariants
-Ability finish always with EndAbility() - (Exm: Activate->PlayMontage-> OnCompleted->EndPlay)
-Ability never use isn't Valid Actor/Avatar (IsValid())
-GameplayEffects for gameplay state/modification. It's don;t 
-CommitAbility for atomicity (It does not need for this testwork (I haven't energy or some other parametrs for realization GA), but it's important practical)
-Don't check only OnCopleted. Check other delegates for return Ability in ValidState
-CanActivateAbility() activation must be available
-Cost/Cooldown checks before ApplyAbility
-Attributes Represen State/Data, never CurrentMontage and other
-Tags describe state, category, Ability
-Ability should manage gameplay
-Effects DataDriven when it's possible

-AbilityActivation != gameplay result

-MovementComponent answer for Jumping, walk and other. GameplayEffect don't influence on this


-Tags describe all what happens with Actor. Use macroses, example: UE_DEFINE_GAMEPLAY_TAG(TAG_Ability_Magic_FireBall,"Ability.Magic.FireBall"), UE_DECLARE_GAMEPLAY_TAG_EXTERN(TAG_Ability_Magic_FireBall) 
-AttributeSets use macros. GameplayEffects reads and writes it, Macros what i need know:
